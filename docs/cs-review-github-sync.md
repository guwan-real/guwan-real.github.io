# GitHub 私有备份与跨设备续练

站点仍是 Astro 静态页面。浏览器直接调用 GitHub REST API，在独立私有仓库 `guwan-real/cs-review-records` 的默认分支保存 `study-records.json`；没有新增服务器、账号系统、代理或数据库，也不把记录提交到公开个人主页仓库。备份提交不会触发主页 Pages 构建。

## 首次连接

1. 打开网站“学习状态”，找到“手机和电脑，接着练”。用户名为 `guwan-real`，仓库为 `cs-review-records`，该私有仓库已经建立。
2. 按页面中的链接在 GitHub 创建 Fine-grained token，设置有效期。Repository access 选择 **Only select repositories**，只选上述备份仓库；Repository permissions 的 **Contents** 设为 **Read and write**。不要授权主页仓库、全部仓库或额外管理权限。
3. 把密钥填入网页，点击“连接并同步”。每台设备都连接同一仓库，可各用独立密钥。
4. 想在浏览器重开后自动连接，可勾选“在这台个人设备保持连接”。默认不勾选，只在当前标签页会话内保持连接。密钥只在 GitHub 生成时显示一次，可以存入自己的密码管理器；不要发到聊天或提交到仓库。

正文、刷题、原有记录和 JSON 备份无需开启同步即可使用。同步设置入口：`/appendix/cs-review/progress/#github-sync`。

## 使用方式

- 连接后打开页面自动同步；本地作答和标记变更会排队同步。自动请求至少间隔 15 秒，前台每分钟检查一次远端，回到页面或联网后也会检查。
- 状态会显示待同步、正在同步、已同步时间或具体问题。换设备前确认显示“已同步”；浏览器立即关闭、后台休眠或断网时不能保证最后一次网络上传完成。
- 手机打开后会取回当前练习，包括题号和未提交选择。模拟考试在提交前只同步选择，不提前生成判分记录或请求题目答案。
- 两台设备开始了不同练习时，未完成的组都会保留。设置区的“其他未完成练习”可选择接续。
- 断开本机连接只移除连接凭据，保留本地学习记录和 GitHub 文件。清空本地学习记录会先断开同步；再次连接会从云端恢复，不能用“清空本地”删除云端备份。
- 密钥过期、撤销或失去权限后暂停同步并提示重新连接，本地刷题继续可用。丢失设备时可在 GitHub 的个人密钥设置中撤销对应密钥。

## 数据与冲突处理

本机 `guwan.cs-review.v1` 数据格式不变，旧记录无需迁移。同步文件使用独立的 `guwan-cs-review-sync` 格式 v1，包含学习数据、字段变更时间、复习标记的取消记录，以及未完成的练习。

- 答题历史按提交 ID 合并；同一组同一题同答案的重复提交只算一次。两个离线设备对同一题提交不同结果时，较新结果用于当前组，另一条以确定的独立 ID 保留，避免丢掉错误历史；反复同步不增加重复条目。
- 收藏、不确定和掌握分别合并，避免不同字段相互覆盖。取消复习带删除标记，旧设备不能把已经取消的状态重新带回来。日期按设备时间记录，合并后的同步时钟保持单调。
- 同组不同题的选择分别合并，已提交题按历史锁定。保留全部未完成练习（最多 64 组）；旧的已完成会话可折叠，但答题历史不删除。
- 更新文件携带已读取的 blob SHA。GitHub 返回冲突时重新读取、合并、重试，单轮最多三次；网络请求期间新增的本地答案继续保留，并排队下一轮上传。
- 损坏 JSON、未知版本、结构不一致、超过 50,000 条提交或 10 MiB，以及本地存储异常时，停止写入并保留原文件。请求超时、断网和限流会提示并重试。

## 凭据与 API 边界

凭据保存在独立的 `guwan.cs-review.github.connection.v1` 项中。仅用户勾选保持连接时才进入 LocalStorage，否则使用 SessionStorage；不会进入普通 JSON 导出、同步文件、页面 HTML、代码仓库或日志。本机同步缓存按用户名和仓库分别保存。

浏览器能读取该站点存储的脚本也能读取持久密钥，因此页面明确告知保存方式，默认不记住，并只接受细粒度密钥。只允许私有仓库，所有请求固定发往 `https://api.github.com`，令牌仅通过 Authorization 头发送，拒绝重定向。不在文件下载 URL、查询串或外部地址发送令牌。连接表单初始禁用，事件处理就绪后才允许输入，避免脚本未加载时原生表单把密钥放进 URL。

超过 Contents API 内联阈值的文件使用精确 blob SHA 读取；保留 10 MiB 上限。GitHub 密钥和本机学习记录不相互混用，原有 JSON 备份仍可独立保存。

依据：[GitHub Contents API](https://docs.github.com/en/rest/repos/contents)、[GitHub 跨域请求支持](https://docs.github.com/en/rest/using-the-rest-api/using-cors-and-jsonp-to-make-cross-origin-requests)、[细粒度密钥与权限](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。

## 验证记录

- 在自动测试中用两个独立存储实例模拟手机与电脑，覆盖同组接续、离线合并、并发冲突、复习取消、收藏字段、模拟考试、损坏文件、过期授权、私有仓库限制和本地空间不足。
- 使用 GitHub CLI 在内部持有的已有授权，实际调用私有仓库 API，验证上传、另一存储实例恢复、继续作答、双向合并和过期 SHA 拒绝。测试使用临时分支，结束后移除；默认分支没有模拟学习记录，也未把 CLI 凭据提取到网页或文件。
- 浏览器验证设置、密钥格式校验、实际跨域请求及无效凭据提示；Safari 内核的原生 fetch 绑定已修正并增加测试。手机响应式视口下无页面横向溢出。
- 真实手机、电脑的首次连接仍由用户生成专用密钥完成；没有声称已在用户设备上完成授权。
