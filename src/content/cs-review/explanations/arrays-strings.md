## 本章的共同问题：能否利用结构减少重复

普通二维数组把每个位置都存下来；对称矩阵有成对相等的元素，稀疏矩阵有大量零，保存全部位置可能浪费空间。字符串匹配也有重复：已经比较成功的字符，失配后能否少比几遍？

压缩存储利用数值位置的规律，KMP 利用模式串内部的前后缀规律。学习时先说清“重复在哪里”，再推导下标或跳转，公式就不再是孤立的记忆题。

## 二维数组地址：先数前面有几个元素

设 `A[m][n]` 使用 0 下标，每元素 w 字节，A[0][0] 地址为 base。行优先表示先存完第 0 行，再存第 1 行；A[i][j] 前面有 i 个完整行和当前行 j 个元素：

```text
行优先：LOC(A[i][j]) = base + (i*n + j)*w
列优先：LOC(A[i][j]) = base + (j*m + i)*w
```

例如 3 行 4 列、base=100、每项 2 字节，行优先的 A[2][3] 前面有 2×4+3=11 项，地址为 122。不是 base+2+3，也不能把字节宽度只乘最后一个下标。[MIT 数组讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec2/)可用于对照连续存储与索引访问的关系。

若行下界为 L1、列下界为 L2，应先转换偏移：行优先为 `base+((i-L1)*n+(j-L2))*w`。题目从 1 编号时，必须同时处理两个维度，不能只把最终答案减一。

## 对称矩阵：把上半部映射到下半部

对称矩阵满足 `A[i][j]=A[j][i]`。只保存含对角线的下三角，n 阶需要 `1+2+...+n=n(n+1)/2` 个位置。

对 0 下标、按行存下三角，映射为：

```text
i >= j 时：k = i*(i+1)/2 + j
i < j 时：先交换 i、j，再套同一公式
```

理由是第 i 行前面的行分别保存 1、2、…、i 个元素，合计 i(i+1)/2，再加本行偏移 j。四阶数组中的存放顺序为：

```text
a00 | a10 a11 | a20 a21 a22 | a30 a31 a32 a33
```

找 A[1][3] 时先用对称性转为 A[3][1]，k=3×4/2+1=7，即压缩数组的第 8 项。压缩下标从 0 还是从 1 开始，会影响最后表示，必须注明。

## 三角、带状和稀疏不要混为一类

三角矩阵某一侧按约定为零或同一常量，只需保存另一侧及必要常量；对称矩阵则是另一侧与已存元素成对相等，恢复规则不同。

三对角矩阵只有主对角线及相邻两条对角线上可能非零。n≥1 时，可能非零位置最多为 `n+(n-1)+(n-1)=3n-2`，其中一些实际也可以为零。题目若问压缩数组长度，还要看是否另外保存常量或边界信息。

稀疏矩阵的非零位置通常没有简单的三角规律，可记录三元组 `(行,列,值)`。例如 3×4 矩阵仅有 `(0,1,5),(2,0,7),(2,3,9)` 三项，仍需保留整体行列数，才能区分尾部全零行、列。

CSR 按行压缩，可用 `values=[5,7,9]`、`cols=[1,0,3]`、`row_ptr=[0,1,1,3]` 表示。第 r 行的数据位于 `[row_ptr[r],row_ptr[r+1])`；第 1 行两指针都为 1，所以为空。转置先交换行列坐标，再按新存储方式排序或重新组织，不能只交换矩阵的行数、列数就结束。

## 字符串匹配：先理解朴素办法哪里重复

文本串 T 是被搜索的内容，模式串 P 是要找的片段。朴素办法把 P 的开头依次对齐 T 的每个可能位置，从头比较；一次失配后右移一个位置重新比较，最坏可能达到 Θ(nm) 次量级，n、m 分别为文本和模式长度。

例如 P 为 ABABC。比较出 ABAB 已经相同，接下来却遇到不相同字符时，先前这四个字符里包含了有用信息：ABAB 的后缀 AB 同时也是 P 的前缀 AB，不必把这两项全部重比。

## 前缀、后缀与 LPS 数组怎样计算

本节用 0 下标，并定义 `lps[i]` 为 `P[0..i]` 的**最长相等真前缀、真后缀的长度**。“真”表示不把整个片段本身算进去。

P=ABABC 的表为：

| i | 当前片段 | 最长相等真前后缀 | lps[i] |
| --- | --- | --- | --- |
| 0 | A | 无 | 0 |
| 1 | AB | 无 | 0 |
| 2 | ABA | A | 1 |
| 3 | ABAB | AB | 2 |
| 4 | ABABC | 无 | 0 |

为什么 ABAB 不写 4？整个字符串不是“真”前缀。为什么不能只看末尾两个字符是否相等？前后缀要求从开头、结尾连续取一段，不是任意位置找相同字符。

教材的 next 数组可能从 1 开始、保存跳转位置，或使用 -1 哨兵；不能看到不同表值就直接认定一方错误。先写定义，再转换。[Cornell KMP 讲义](https://www.cs.cornell.edu/courses/cs312/2002fa/lectures/lec26.htm)也采用已匹配前缀与后缀重合的信息进行跳转。

## KMP 失配时具体怎样继续

在文本 ABABABC 中找模式 ABABC。i 指文本当前字符，j 表示已经匹配的模式长度，也是下一待比较模式下标：

1. 开始 i=0、j=0，依次匹配四个字符 ABAB，来到 i=4、j=4。
2. T[4]=A，P[4]=C，失配。已匹配片段 ABAB 的 lps[3]=2，令 j=2，i 保持 4。
3. 这表示保留已经知道相等的后缀 AB，继续比较 T[4] 与 P[2]，二者都是 A。
4. 再匹配 B、C，j 达到模式长度 5，找到从文本下标 2 开始的匹配。

这里回退的是模式状态，不回退文本 i。也不是“失配字符完全不比较了”，同一个文本字符可能与较短模式状态重新比较。

核心匹配过程可写成：

```text
j = 0
for i = 0 .. n-1:
    while j > 0 and T[i] != P[j]:
        j = lps[j-1]
    if T[i] == P[j]:
        j = j+1
    if j == m:
        return i-m+1
```

该片段假定模式非空；空模式的返回约定需要先单独处理。要找全部匹配时，找到一次后还应按前后缀状态继续，而不是继续访问越过末尾的 P[m]。

## LPS 本身也可以用已经求出的结果构造

不必对每个前缀重新枚举全部前后缀。设正准备处理模式位置 i，j 是前一片段已经得到的最长重合长度：若 P[i] 与 P[j] 相同，可以把这段重合延长 1；若不同，先退到更短的候选前后缀 `lps[j-1]`，再试。

```text
lps[0] = 0
j = 0
for i = 1 .. m-1:
    while j > 0 and P[i] != P[j]:
        j = lps[j-1]
    if P[i] == P[j]:
        j = j+1
    lps[i] = j
```

对 ABABC，处理第二个 A 时可接在前缀 A 上，得到长度 1；再处理 B，延长为 2。处理末尾 C 时，原候选想与 P[2]=A 延续，失败；回退到更短候选后仍无法与开头 A 匹配，得到 0。

构造与匹配是两件相连的工作：构造只分析模式本身，匹配才读文本。改换文本不要求重新分析同一个模式；改了模式，则旧 LPS 通常不能直接沿用。要在纸上核对一个表，先用定义逐项找真前后缀，再用递推过程确认跳转，避免只记住一串数字。

压缩矩阵也有同样的“省什么、付出什么”问题：少存元素可以省空间，但访问时要做映射，插入新非零项可能要调整索引结构。压缩不是把普通数组截短后仍按原二维下标随意读写，必须连同还原规则一起设计。

## 为什么 KMP 总量仍为线性

while 可能看起来嵌在 for 里，但不能直接判成平方。j 每次成功匹配最多增加 1，总增加次数不超过文本扫描量；失配回退使 j 严格变小，j 又不能为负，因此总回退次数也受到此前增加次数约束。

预处理 LPS 用相同的复用思想可在 Θ(m) 时间完成，文本匹配为 Θ(n)，合计 Θ(n+m)，LPS 需要 Θ(m) 辅助空间。主串不回退是关键特征之一，但要由总工作量分析得出线性结论，不能把它当作不需解释的口号。

## 做题与自查

矩阵题先写下标下界、存储方向、含不含对角线、元素宽度，再数“前面完整部分+当前偏移”。KMP 题先写 next/LPS 定义，列前后缀，失配时只调整模式状态并检查当前文本字符是否还能复用。

自查：四阶对称矩阵保存含对角线的一半需要几项？**10 项。**A[1][3] 在本章压缩规则中的下标？**7。**ABAB 的 LPS 是 4 吗？**不是，是 2。**KMP 失配后文本指针必须退回起点吗？**不需要。**

## 资料题型补充：反求数组尺寸与辨认 C 指针类型

地址题也可能反过来给两个元素位置，让你先求每行长度。设按行优先、零基下标，每元素2 B，A[0][0]地址1000，A[2][2]地址1052。地址差52 B对应26个元素，所以 `2×列数+2=26`，列数为12。再求A[3][4]：前面有 `3×12+4=40` 个元素，地址为 `1000+40×2=1080`。不能直接把字节差当作元素差，也不能在只给两处地址时忽略存储次序。

C语言中的“数组指针”和“指针数组”只差词序，含义却不同。`int (*p)[5]` 中括号使 p 先与 `*` 结合，p是一个指针，指向含5个int的一行；`int *q[5]` 中q是一个5元素数组，每格保存一个int指针。若题设int为4 B、指针为8 B，则p本身占8 B，p+1跨过5个int即20 B，而q整体占5×8=40 B。指针本身占几字节与它一次跨过多长对象，是两个问题。

这里的数值只是题设，不是所有机器的统一大小；计算sizeof还要确认对象有没有在函数参数位置退化为指针。初学先能读清“p是一个指针，q是一组指针”，不需要把指针理解成某种会自动复制数组的容器。
