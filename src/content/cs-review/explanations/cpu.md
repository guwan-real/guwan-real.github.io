## 数据通路做事，控制器安排做什么

CPU 不是只有一个计算器。**数据通路**包含寄存器、ALU、连接通路和选择器，负责保存、运算与传送；**控制器**根据指令和状态，产生读写寄存器、选择 ALU 操作、访问存储器等控制信号。

常见教学寄存器有：PC 保存接下来取指的位置；IR 保存当前指令；通用寄存器保存操作数与结果；状态寄存器保存规定的条件标志。MAR 表示存储器地址寄存器，MDR 表示存储器数据寄存器，它们常用于解释访存流程。具体处理器可能用不同组织，不必要求所有名称都对应一颗独立可见寄存器。

例如一条加法指令，控制器安排读取两个源寄存器，ALU 相加，再将结果写目的寄存器；同样的 ALU 和寄存器在下一条指令中又可通过不同信号执行别的操作。

## 一条指令从哪里开始

教学五级流程可以记成：**IF 取指 → ID 译码并读取寄存器 → EX 执行或计算地址 → MEM 访存 → WB 写回**。不需要内存读写的指令在 MEM 阶段可能没有有效访存工作；并不是每种指令都做同样的数据操作。

对 `LOAD R1,0(R2)`，EX 计算地址，MEM 读取对应内存，WB 把取到的数据写入 R1。对普通寄存器 ADD，EX 产生加法结果，WB 写回；不要把 EX 与所有访存步骤混成一件事。

**时钟周期**是基本时钟节拍；**指令周期**覆盖完成一条指令所需的全过程；传统教材还用机器周期 / 总线周期表示一次基本操作的组织单位。它们之间的固定倍数必须由具体机器给出，不能默认一条指令只要一个时钟。

## 流水线为什么能提高吞吐量

像工序分站处理：第一条指令进入下一站时，第二条指令就能进入第一站。不必等第一条完成全部阶段才开始第二条。以下假定五级各 1 周期、没有冒险与停顿：

| 指令 | 周期1 | 周期2 | 周期3 | 周期4 | 周期5 | 周期6 | 周期7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| I1 | IF | ID | EX | MEM | WB | | |
| I2 | | IF | ID | EX | MEM | WB | |
| I3 | | | IF | ID | EX | MEM | WB |

三条指令在 7 个周期内完成；若每条按 5 阶段依次执行完再开下一条，则要 15 个阶段时间。理想 k 级、n 条指令总周期是 $k+n-1$；非流水为 $nk$，假定每级耗时相同且忽略额外寄存器开销。

**单条指令延迟不一定缩短**：第一条仍经过 5 级。主要改善的是后续指令完成的频率。级数增加还可能因级间寄存器延时、阶段不平衡、分支代价而收益变小。

## 三类冒险各是什么冲突

| 类别 | 为什么不能照理想时间表走 | 例子 | 处理思路 |
| --- | --- | --- | --- |
| 结构冒险 | 多条指令争同一硬件资源 | 取指与数据访问争单端口存储器 | 增加 / 分离资源或暂停 |
| 数据冒险 | 一条指令需要前面尚未就绪的结果 | ADD 写 R1，下一条立刻读 R1 | 转发、停顿、合理调度 |
| 控制冒险 | 尚不确定接下来执行哪条指令 | 条件分支结果未确定 | 预测、延后取指、错误时冲刷 |

RAW 是“后读前写”：后指令读到前指令产生的数据，是常见真相关。WAR 与 WAW 涉及反相关 / 输出相关；它们在特定简单顺序流水线中未必形成冒险，在乱序等更复杂实现中才需要相应机制。**有依赖不等于一定停顿，是否停顿取决于数据何时就绪及硬件能力。**

## 转发为什么也不能解决所有等待

转发把执行单元已经产生的结果直接送给后续需要它的位置，不必等先写回寄存器、后再读出来。它绕过的是保存 / 读取的等待，不是让结果在计算前就存在。

自编模型：五级单发射顺序流水线，有 ALU 转发；LOAD 的数据在 MEM 后才可用，因此紧邻 load-use 需停顿 1 周期。

```text
I1: LOAD R1,0(R2)
I2: ADD  R3,R1,R4
I3: SUB  R5,R3,R6
```

理想 3 条 5 级是 7 周期；I2 依赖 I1 的加载值，按此题设增加 1 周期；I3 对 I2 的 ALU 结果可转发，不额外停顿，所以共 8 周期。若题设改为无转发、不同读写时刻或不同流水级数，结果就要重新画表。

**气泡**是停顿造成的空工作位置；**冲刷**是把走错路径等情况下已经进入流水线的指令作废。二者都可能损失性能，但原因不同。

## 硬布线与微程序控制

硬布线控制用逻辑电路直接根据指令与状态产生信号，通常追求较快响应，但复杂控制的设计修改可能困难。微程序控制把较复杂的控制过程写成一系列微指令，放在控制存储器中，再由微顺序控制执行。

**机器指令不等于微指令**：软件看到的 ADD 是 ISA 指令；内部可能以若干微操作实现。微程序也不等于用户写的应用程序。两种控制方式是实现取向，实际产品可以组合使用，不能仅凭某 CPU “很快”就断定它完全不用微程序。

## 中断：先暂停、保存，再处理和返回

外设完成、定时器到期等事件可能请求 CPU 处理。CPU 在满足规定条件时响应，保存必要的返回信息与状态，转入中断处理程序，处理后恢复现场并返回。保存哪些寄存器、由硬件还是软件保存，因体系结构与操作系统而异。

**中断请求 ≠ 立即响应**：屏蔽状态、优先级、当前执行阶段等都影响响应。向量中断通过向量等机制确定处理入口；轮询则通过检查来源识别需要处理的事件。

常见教学区分把外部异步事件称中断，把执行当前指令产生的同步问题称异常；系统调用可通过受控陷入进入内核。不同体系的总称有差异，按题设术语判断。恢复返回地址还要看异常是重试当前指令还是继续下一条，不能一概处理。

## 流水线题的固定检查表

先列每级耗时、资源是否共享、结果在哪级产生、后继在哪级需要、是否转发；再画无冲突时间表；按依赖逐项插入气泡；最后计算尾指令完成时刻。分支题额外写清预测规则和冲刷损失。只背 $k+n-1$ 而不读这些前提，是此类题最常见的失分原因。
