## 数据结构是怎样组织数据与操作的

一份待办事项可以保存为数组，也可以保存为链表；文件目录可以表达成树，城市道路可以表达成图。选择结构的目的，是让经常发生的操作容易实现，而不是替数据挑一个漂亮的名字。

学习时分开三个问题：**元素之间是什么关系、元素在机器中怎样保存、允许执行哪些操作**。例如“第一个任务在第二个任务前面”属于逻辑顺序；“两个任务在连续内存还是由指针相连”属于存储安排；“按位置读取、插入和删除”属于运算。

| 视角 | 例子 | 不要混淆 |
| --- | --- | --- |
| 逻辑结构 | 集合、线性结构、树形结构、图结构 | 线性关系不要求物理地址连续 |
| 存储结构 | 顺序、链式、索引、散列等 | 顺序存储不代表关键字已排序 |
| 操作 | 查找、遍历、插入、删除等 | 同一操作在不同实现中成本不同 |

抽象数据类型 ADT 约定数据与操作的语义，不限定具体实现。栈规定后进先出，可用数组或链表实现。接口相同不等于成本相同：数组是否需要扩容、链表是否需要分配结点，都会影响执行。

## 算法先要正确，再讨论快慢

算法是解决某类问题的明确步骤。传统基础定义强调有穷性、确定性、可行性，以及输入和输出：对合法输入，步骤应能够执行，并在有限步骤后给出规定结果。

“找到最大值”不是完整算法，仍需说明怎样扫描、初值是什么、空输入如何处理。对非空数组，可先令最大值为第一个元素，再逐个比较剩余元素。不能随意令初值为 0，否则全是负数时会出错。

复杂度分析建立在输入范围和计算模型上。本章默认一次普通比较、赋值、数组下标访问等是常数成本。若整数可任意长、比较的是很长字符串，单次操作成本还需要进一步分析。[MIT 算法导论讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec1/)可用于对照问题、正确性与效率的关系。

## 复杂度数的是执行次数，不是代码行数

设 n 为输入元素个数，选一种代表性的基本操作计数。下面外层走 n 次，但内层次数随 i 变化：

```text
for i = 0, 1, ..., n-1:
    for j = 0, 1, ..., i-1:
        work()
```

当 n=4，work 分别执行 0、1、2、3 次，总计 6 次。一般为 `0+1+...+(n-1)=n(n-1)/2`，增长量级为平方。代码只有三行，不代表三次操作。

若两段循环顺序执行，一段 n 次、一段 n² 次，总量是 n+n²，取主项得到平方阶。若内循环每次独立执行 n 次，外循环也 n 次，总量才是 n×n。循环嵌套不应一律机械相乘，要先看范围是否依赖外层变量。

再看 `i=1; while i<n: i=i*2`。n=8 时，i 依次为 1、2、4，循环体执行 3 次，然后变成 8 退出；一般约为 log₂n 次。每次减半的过程同理，关键在于规模成倍改变。

## O、Ω、Θ 与最好、平均、最坏不是同一分类

O 表示渐近上界，Ω 表示渐近下界，Θ 表示同一量级的紧确界。比如 `3n+2` 是 Θ(n)，当然也可以说它是 O(n²)，但后者上界不够紧，通常不适合作为题目要求的最精确量级。

渐近分析忽略固定常数和低阶项，是为了比较规模增大后的增长趋势，不是承诺某个程序在所有小输入上都更快。[MIT 渐近记号讲义](https://live.ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/c6d8f06c6f11e3342633dec85498f551_MIT6_006S20_r01.pdf)给出了上、下界的正式定义。

最好、平均、最坏则描述相同规模下考虑哪些输入。例如顺序查找：目标恰在首位时只比一次；目标在末位或不存在时可能比 n 次；平均次数还要有位置概率假设。可以说“最坏时间为 Θ(n)”，也可以说“最好时间为 Θ(1)”，二者并不矛盾。

不要把“大 O”自动读成“最坏”，也不要把“平均”理解成最好与最坏的算术平均。平均复杂度需要对输入或随机选择建立明确模型。

## 递归既要数总工作，也要数同时活跃的调用

假设递归求前 n 项和，每次只调用一次规模 n-1 的子问题，返回后做一次加法。时间满足 `T(n)=T(n-1)+Θ(1)`，总计 Θ(n)；但在最深处，可能同时保留 n 层调用，栈空间为 Θ(n)。

若递归每次只处理一半规模并做常数工作，递推为 `T(n)=T(n/2)+Θ(1)`，时间和常见递归栈深度都是 Θ(log n)。若每次处理两个一半规模子问题，再用线性时间合并，则为 `T(n)=2T(n/2)+Θ(n)`；每层合计线性工作，约 log n 层，总时间 Θ(n log n)。

主定理可以分析特定形式的递推，但不能套到所有递归。先确认子问题个数、规模和额外工作；`T(n-1)` 与 `T(n/2)` 的增长完全不同。带切片复制的程序也不能把每层额外成本直接当成常数。

## 空间复杂度看峰值，均摊复杂度看一串操作

辅助空间常指输入之外所需的额外空间，是否计输出应按题设。几个变量通常为 Θ(1)；长度为 n 的临时数组通常为 Θ(n)；递归还要计同时存在的调用帧。

“循环执行 n 次，每次用一个临时变量”并不是 Θ(n) 空间，因为这些变量可以复用，峰值仍为常数。反过来，代码里只有一句递归调用，也可能累计线性栈空间。

动态数组扩容能说明**单次最坏与均摊**的区别。容量满时，若从 4 扩到 8，需要分配新空间并复制旧元素，这一次追加可能花线性时间；大多数普通追加只写一个位置。若容量按固定倍数增长，把一串追加中的复制成本合计后平摊，每次追加可以达到均摊常数成本。[MIT 动态数组讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec2/)解释了这类分析。

均摊不是概率平均：即使没有随机输入，也可以对最坏的一串操作证明总成本上界。它也不意味着每次操作都在常数时间完成。

## 用循环不变式解释“为什么算对了”

一个算法在几个样例上运行正常，不足以证明对全部合法输入正确。循环不变式是一种说明方法：找出每轮开始或结束都保持的事实，再检查初始化、维持与终止。

例如扫描非空数组找最大值，处理完前 k 个元素时，不变式是“变量 best 等于这 k 个元素的最大值”。初始只处理第一个元素，把 best 设为它，不变式成立；加入第 k+1 项时，取 best 与新元素较大者，恰好得到前 k+1 项的最大值；扫描结束时 k=n，所以得到整个数组的最大值。

这样还能定位错误：如果初值写成 0，对全负数组，不变式在第一步就不成立。证明不是给代码附加一段漂亮解释，而是在检查它依赖什么条件、什么时候可能失败。

规模也要与问题相符。一个 n 行 n 列矩阵有 n² 个位置，逐项读完整个矩阵是 Θ(n²)，并非因为“只扫一遍”就称 Θ(n)。图算法常同时使用顶点数与边数；若先排序再查找，还要决定题目是只问一次查询，还是包含排序准备成本。

## 做题与自查

分析题依次写：输入规模是什么 → 基本操作是什么 → 实际次数的求和或递推式 → 渐近量级 → 最好、最坏或平均的条件 → 辅助空间峰值。问准确次数就保留常数，问量级才消去常数与低阶项。

自查：顺序存储的数据一定有序吗？**不一定。**两个独立 n 次循环是平方时间吗？**通常是线性总量。**递归时间为线性，空间一定常数吗？**不一定，还要看调用深度。**均摊常数是否排除偶尔线性扩容？**不排除。**
