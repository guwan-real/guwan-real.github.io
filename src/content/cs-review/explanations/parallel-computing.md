## 并发与并行分别在说什么

**并发**强调多个任务在一段时间内交替推进；**并行**强调同一时刻实际执行多个操作。单核可以靠切换任务实现并发，但不能因此说同一时刻执行了多核规模的指令；多核可以支持真正并行，也仍需调度和同步。

例如一位工作人员交替处理两份工单，是并发；两位工作人员同时各处理一份，是并行。这个类比用于理解，实际 CPU 的流水线、向量执行等还可在指令内部提供不同层次的并行。

**任务并行**把不同工作分给不同执行者，如一个核解析日志、另一个核生成图表；**数据并行**把同类运算分到不同数据片段，如同时计算一万个传感器读数的平均值。一个应用可以结合两种方式。

## Flynn 分类：数指令流与数据流

| 类别 | 指令流 / 数据流 | 直观解释 | 例子或注意 |
| --- | --- | --- | --- |
| SISD | 单 / 单 | 一个指令流处理一个数据流 | 简化串行模型 |
| SIMD | 单 / 多 | 一条指令对多个数据元素做同类运算 | 向量加法、CPU 向量指令 |
| MISD | 多 / 单 | 多指令流处理同一数据流 | 较少见，具体系统分类有争议时按定义分析 |
| MIMD | 多 / 多 | 多个执行者跑各自指令、处理各自数据 | 常见多核和多处理器组织 |

例如向量指令一次把四对数相加，不代表有四个各自运行任意程序的 CPU。GPU 常用 SIMT（单指令多线程）模型组织大量线程，与 SIMD 有联系，但不能仅凭名称把线程模型和向量 ISA 视为完全相同。

## 为什么 GPU 适合有些任务，却不是所有任务

CPU 强调通用控制、低延迟和复杂分支等能力；GPU 为大量并行的相似运算提供高吞吐资源。矩阵、图像与大批独立数值运算容易出现数据并行，因而常适合 GPU。

但先把数据送到设备、启动计算、等待并同步、把结果取回，都要时间。一个只用 CPU 算 1 ms 的小任务，即使 GPU 核心运算只需 0.1 ms，如果传输与启动花 3 ms，总共仍是 3.1 ms，反而更慢。

**线程分歧**表示同一执行组中线程走不同分支，可能降低有效利用率；访存不规则、算量太小、同步频繁或显存带宽受限，也会拖慢。GPU 适合什么任务，要看整体数据移动与执行模式，不是只比较核心数量。

## 加速比和并行效率

设相同规模问题单处理器时间为 $T_1$，使用 p 个处理器时间为 $T_p$：

$$S_p=T_1/T_p,\qquad E_p=S_p/p$$

自编例子：单核处理 40 s，8 核处理 10 s，则加速比 4，并行效率 $4/8=50\%$。它表示相对理想线性加速利用得怎样，不等于直接读到的每个核硬件占用率。

如果只把“8 核”代进加速比答案，等于预先假定没有串行部分、通信、调度和负载不均。实际这些开销恰恰是要分析的因素。

## 固定规模问题：Amdahl 的时间账本

旧总时间中串行部分为 $1-q$，可并行部分为 q；若 q 部分理想分给 p 个处理器，且暂不计额外开销：

$$S_p=\frac{1}{(1-q)+q/p}$$

例如 q=0.9、p=4：新时间比例 $0.1+0.9/4=0.325$，加速约 3.08；p 无限大也只有 $1/0.1=10$。串行部分不会因给可并行部分再添核就自动消失。

若还存在通信开销比例 c，可先用时间模型写 $T_p/T_1=(1-q)+q/p+c$，按题设判断 c 是否随 p 改变。公式帮助表达前提，不是保证任何系统都按这条简单曲线变化。

## 扩大问题规模：Gustafson 换了观察角度

Amdahl 通常固定问题规模，问“同样的事能快多少”。Gustafson 常固定并行运行时间，让更多处理器做更大规模的工作，问“相近时间能做多少事”。若并行运行中的串行时间比例为 α，简化的缩放加速比为：

$$S=p-(p-1)\alpha$$

例如 p=8，α=0.1，缩放加速比为 7.3。这与上一公式的比例基准不同，不能拿一个题里的 q 直接不加解释当另一个公式的 α，也不能说 Gustafson“推翻了串行部分限制”。两者研究的是不同规模假设。

## 共享内存与分布式内存

共享内存让多个执行者通过共同地址空间交换数据，编程时要处理竞争与同步；NUMA 系统虽然共享地址空间，不同内存位置访问代价仍可能不同。

分布式内存中，各节点有自己的内存，常通过消息传递交换结果；扩展能力较强，但通信、失败与数据划分更重要。集群不只是把多台机器摆在一起，还需要任务分配、网络与协作机制。

**负载均衡**让各执行者工作量尽量接近，否则最慢的分片拖住整体。例如四核任务量为 1、1、1、9 秒，即使总工作量 12 秒，也不能在 3 秒内完成。可以更细分任务或动态分配，但调度本身也有成本。

## 正确性：快之前先保证没有算错

两个线程同时执行 `count++`，可能各自读到同一个旧值，再各自写回同样的新值，导致少加一次。这个复合动作不因一行代码就自动原子。

互斥锁保护临界区；原子操作提供特定操作的原子性及规定的内存顺序；屏障让参与者在某点会合。原子不等于没有任何性能代价，锁也不保证不会死锁，仍要设计一致的获取顺序与合理范围。

**Cache 一致性**主要约束共享位置的副本如何保持协调；**内存一致性模型**说明程序可以依赖怎样的访存可见顺序。它们相关但不同。不能因为“缓存是相干的”，就认定多个普通读写组成的整体操作天然原子。

## 异构计算：按任务特征分工

异构系统组合不同计算单元，如 CPU 负责控制与调度，GPU 加速密集数值，其他加速器处理特定工作。关键不是把所有任务移走，而是选择适合的部分，并考虑数据格式转换、传输与功耗等约束。

做题先判断任务是数据并行还是大量串行依赖；再列计算、传输、同步和等待的总时间；涉及加速比时圈出固定 / 扩展规模。能解释“核心越多为何不总是越快”，比背下每种设备名称更重要。

## 资料补讲：超流水、超标量与VLIW怎样区分

三者都可能提高指令级并行，但改变的环节不同。**超流水**把工序分得更细，可能缩短节拍；**超标量**让处理器在一个周期内按相关性与资源条件发射多条指令；**VLIW超长指令字**由编译器等把可并行操作显式组合进一个较宽指令，多个操作字段对应相应执行资源。不能把“更细的流水级”和“同拍发射多条”当同义词。

例如有12条独立指令，题设单发射每周期最多发1条，需要至少12个发射周期；双发射且资源充足时可减为6个**发射周期**。这不意味着全部指令只用6周期就完成，还应计流水填充、结果延迟和停顿。若后11条都依赖前一条的结果，即使硬件支持双发射，也未必达到这个理想值。

这类题先圈“发射、执行、完成”中的哪一个词，再看是硬件动态选择多条、细分流水阶段，还是软件打包多个操作。指令级并行不等于一台芯片里一定有多个可各自运行任意程序的核心。
