## 总线是约定好的信息通路

CPU、内存和设备要交换信息，需要约定“谁发起、选哪个位置、传什么、什么时候有效”。传统总线把一组共享信号线及其协议组织在一起；现代互联也可以是高速串行点对点链路，不必都长得像很多设备挂在同一组平行导线上。

**地址信号**表达访问哪个位置；**数据信号**搬运实际值；**控制信号**表达读 / 写、请求 / 应答、时钟等控制。地址、数据可以复用部分物理引脚，在不同阶段承载不同含义；因此总线逻辑位宽不能不加分析就等于芯片引脚总数。

在简单 CPU 主控模型里，地址常由 CPU 发向存储器或外设，数据可双向；但有 DMA 等其他主设备时，不能把“地址永远只能由 CPU 发出”当所有系统的绝对规则。

## 看一次简化读操作

以下是教学顺序，不是某型号处理器的精确电气时序：

1. 主设备获得使用通路的权利，把目标地址放到地址线上。
2. 发出读控制，使被选中的设备知道要提供数据。
3. 从设备译码地址、准备数据，必要时用等待 / 应答信号告知尚未就绪。
4. 数据稳定后，主设备在协议规定的时刻采样。
5. 撤销控制并结束本次传输，满足规定的保持时间后再切换信号。

**建立时间**指采样前信号要稳定多久；**保持时间**指采样后还要保持多久。看时序图先找采样边沿、有效电平和等待状态，不能把两条线恰好画得相交就当成正确采样。

同步总线依靠共同的时钟关系规定动作；异步总线靠请求 / 应答等握手推进。异步不是“随便什么时候都可读”，而是改用握手约束先后；同步总线也可能插入等待周期。

## 地址线决定多少地址，数据线决定每次多宽

n 根二进制地址线最多区分 $2^n$ 个地址单元。如果按字节编址，24 根地址线理论覆盖 $2^{24}$ B，即 16 MiB；如果每个地址单元是 16 bit，则同样的地址数对应 32 MiB 数据容量。

32 位数据总线通常每次搬运 32 bit，即 4 B。它不自动说明地址线是 32 根，也不说明总地址空间只有 4 B。**地址位宽、数据位宽、机器字长是三个要分开看的概念。**

## 带宽题先算一次能传多少，再算每秒多少次

$$\text{理论数据带宽}=\text{每次传输字节数}\times\text{每秒有效数据传输次数}$$

自编例子：数据线 32 位，时钟 100 MHz，每次传输占 2 个周期。每次 4 B，每秒最多 $100\times10^6/2$ 次，所以理论带宽 200 MB/s（十进制），不是 400 MB/s。若每周期可传两次，或一次事务含多个数据拍，则要按题设重新数数据传输次数。

若题目再给每个事务额外有地址、仲裁、校验等开销，应按“有效数据量 / 全部耗时”算有效吞吐。例如传 16 B 的数据本身需 4 个周期，地址与等待另用 2 个周期，总用 6 个周期；不能只除以 4。

峰值带宽是假定理想连续传输的上限，实际会受协议开销、设备速度、争用和访问模式影响。单位 bit/s 与 byte/s 相差 8 倍，MHz 也不是 MB/s 的同义词。

## 多个主设备争用时怎么办

仲裁决定谁先使用共享资源。**集中式仲裁**由一个仲裁部件决定；**分布式仲裁**由参与者按协议共同决定。固定优先级实现简单，却可能使低优先级长时间等待；轮转可改善公平性，但也有控制开销。

菊花链优先级常与链中位置有关，结构简单但可能有传播延迟和位置相关不公平。具体方案的优劣要结合题目，不存在“优先级越高，所有设备总吞吐必然越高”的结论。

## 查询、中断、DMA：谁在等待、谁搬数据

| 方式 | CPU 做什么 | 适合怎样理解 |
| --- | --- | --- |
| 程序查询 | 反复检查设备状态，再按程序搬运 | 简单，但忙等浪费 CPU 时间 |
| 中断方式 | 设备需要处理时通知 CPU，处理程序参与传送 | 减少持续轮询，但频繁中断也有代价 |
| DMA | CPU 配置传输，DMA 机制在设备与内存间搬运块数据 | 大块数据时可减少 CPU 逐项搬运负担 |

DMA 不表示完全不需要 CPU：CPU 仍可能配置地址和长度、处理完成通知与错误，并关注地址映射与缓存一致性。DMA 地址也不一定等于程序看到的虚拟地址，不能把一个普通指针直接当任何设备都能使用的地址。

## 设备寄存器怎样被程序访问

**存储器映射 I/O（MMIO）**把设备寄存器映入某些地址区域，以体系规定的访存机制访问；这些地址不表示背后一定是一块普通 RAM。设备寄存器读写还可能带副作用，需要遵守顺序与访问宽度。

**独立编址 I/O**给端口独立空间及专门访问指令，是另一种组织方式。二者区别是地址空间与访问机制，不是“哪个使用真实设备、哪个只模拟设备”。

## 常见接口怎样抓特征

| 接口 | 入门特征 | 注意 |
| --- | --- | --- |
| I²C | 常见双线串行、时钟与数据线、地址选择设备 | 支持协议规定的仲裁与多控制器情况，不只限固定单主 |
| SPI | 常见同步串行、时钟 / 数据 / 片选 | 线数与双向方式依具体变体；不是完整统一的高层设备协议 |
| UART | 常见异步串行、起止位约定帧 | UART 与 RS-232 的电气标准不是同一概念 |
| USB | 主机管理的串行总线体系 | 传输模式、速率取决于版本和设备 |
| PCIe | 串行点对点链路，多通道扩展 | 不应因名字带“总线”就当传统共享并行 PCI |

此处只比较组织特征，不要求背各版本最新速率。做接口选择题时先辨同步 / 异步、串行 / 并行、共享 / 点对点，再看题目给的距离、速率和设备约束。

## 复习检查

能说清“24 根地址线为什么不等于 24 bit 数据宽度”吗？能在给定每事务周期数时算出带宽吗？能解释 DMA 为什么仍有 CPU 参与吗？时序图题只需遵循图上的有效电平、建立保持和采样关系，不应凭背诵某个型号的波形替代题设。

## 资料补讲：容量相同，字节地址与字地址的范围不同

容量64KiB、每字32位即4B：按字节编址有65536个地址，若从0开始，到`FFFFH`；按字编址只有 $65536/4=16384=2^{14}$ 个地址，到`3FFFH`，最少14位地址。不能因为字长32位，就把它当成32根地址线或 $2^{32}$ 个实际单元。

`16K×32bit`芯片有16K个位置，因此需要14位二进制地址，数据宽32位；仅把非复用的逻辑地址线与数据线相加是46根。这个数不含片选、读写、电源等引脚，也不能直接作为所有封装的总引脚数，地址数据复用还会改变物理引脚组织。

“总线分三类”也有不同分类维度。按信息性质分地址、数据、控制信号；按连接对象又可讨论处理器、主存、I/O及DMA等通路。“三总线结构”若没有图或教材定义，不宜仅凭数字三断言就是同一套分类。答题先把它是在数信号类别还是功能通路写清楚，再谈带宽与接线。
