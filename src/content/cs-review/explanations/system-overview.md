## 一台计算机怎样完成一条指令

可以先把计算机理解成几个协作部件：**存储器保存指令与数据，运算器处理数据，控制器协调操作，输入输出部件联系外界**。CPU 通常包含运算器、控制器和寄存器；内存不等于 CPU 里面的寄存器。

例如程序想计算 `a+b`：CPU 取到指令，判断要做加法，获取 a、b，把它们送入算术逻辑单元 ALU，再把结果保存。具体机器可能用多条指令完成这件事，但“取指—识别—执行—保存”的主线相同。

| 部件 | 工作 | 容易混淆 |
| --- | --- | --- |
| CPU | 执行指令、控制程序运行 | 主频不是衡量一切任务速度的唯一指标 |
| 寄存器 | 保存正在用的操作数、地址与状态 | 数量少、很快，通常属于 CPU 内部 |
| 主存 / 内存 | 存放运行中的程序和数据 | 通常用 DRAM，断电后内容不能可靠保留 |
| Cache | 缓存近期或邻近的内存块 | 是存储层次，不是磁盘备份 |
| 外存 | 长期保存文件 | SSD/HDD 容量较大，但访问特性不同于内存 |
| I/O 与互联 | 连接设备并搬运信息 | 不意味着每个数据字节都由 CPU 逐字节复制 |

**冯·诺依曼思想**的重要内容是存储程序：把程序像数据一样编码后存入存储器，按指令运行。指令和数据都是位串，区别来自 CPU 在什么位置、以什么方式解释它们。现代处理器可以有分开的指令 Cache 和数据 Cache，不必据此断言不再采用存储程序思想。

## 软件与硬件之间隔着哪些层

由底向上看，可把层次想成：数字逻辑 → 微体系结构 → 指令集 ISA → 操作系统与运行环境 → 程序语言和应用。它是理解分工的模型，不要求每个系统都按完全相同名字划层。

**ISA（指令集体系结构）**规定软件可见的指令、寄存器、数据类型和访存等行为，像软硬件双方遵守的合同。**微体系结构**决定如何实现这份合同，例如流水线深度、Cache 组织和执行单元数量。两颗 CPU 可以实现同一 ISA，但内部设计和性能不同。

编译器把较高级的源程序转换为目标表示，汇编器把汇编指令转换成机器码，链接器连接目标文件与库，加载器把可执行程序放到运行环境。解释执行是在运行时分析、执行某种程序表示；即时编译 JIT 又可以把热点代码转成本机码。因此“编译语言永远只编译一次、解释语言完全不编译”是过度简化。

固件是靠近设备、承担底层控制的软件，常存于非易失存储器。它仍是程序，不因保存在芯片里就自动变成组合逻辑电路。

## 时钟频率与周期：先统一单位

时钟用周期性信号协调操作。频率 $f$ 表示每秒多少周期，周期 $T$ 表示每个周期多长：

$$T=1/f$$

**自编例子**：2 GHz 是每秒 $2\times10^9$ 个周期，因此周期为 $0.5$ ns。要算 6 个周期的时间，就是 $6\times0.5=3$ ns，而不是 6/0.5。

常用单位换算：1 s = $10^3$ ms = $10^6$ μs = $10^9$ ns；1 GHz = $10^9$ Hz。题目中小写 b 常指 bit，大写 B 指 byte，1 B = 8 bit；KiB 明确表示 1024 B，而工程中的 MB/s 常按十进制，先看约定。

## IC、CPI 与 CPU 执行时间

**IC** 是程序实际执行的指令总数；**CPI** 是平均每条指令消耗多少时钟周期。如果不同类别指令的 CPI 不同，要用实际执行比例加权，不是简单平均类别数。

$$\text{CPU Time}=\text{IC}\times\text{CPI}\times T=\frac{\text{IC}\times\text{CPI}}{f}$$

例如某程序执行 100 万条指令，其中 80% 是 CPI=1 的指令、20% 是 CPI=4 的指令。平均 CPI 是 $0.8\times1+0.2\times4=1.6$。在 2 GHz CPU 上，CPU 时间为：

$$\frac{10^6\times1.6}{2\times10^9}=0.0008\text{ s}=0.8\text{ ms}$$

如果换机器后主频上升，但指令数或 CPI 也上升，不能只看 GHz 就判更快。例如 B 的主频是 A 的两倍、同程序 CPI 却是三倍且 IC 相同，则 B 的 CPU 时间是 A 的 $3/2$。

**CPU 时间与总耗时不同**：总耗时还可能包含等待磁盘、网络、排队等。程序等待网络时 CPU 并不一定都在为它计算，所以把所有响应时间都代进 CPU 公式可能错。

## 响应时间、吞吐量与性能

**响应时间 / 延迟**关心一次任务从开始到完成要多久；**吞吐量**关心单位时间完成多少任务。批量并行可能提高每分钟处理量，同时让单个任务等待更久，这两项不能互换。

如果同一任务在旧机器用 12 s、新机器用 8 s，加速比是 $12/8=1.5$，表示新性能是旧的 1.5 倍；耗时减少比例是 $(12-8)/12=1/3$。不能把“加速 50%”不加说明地等同于“时间减少 50%”。

MIPS 是每秒百万条指令，浮点操作率描述每秒完成多少浮点操作。它们可帮助分析规定工作负载，但跨 ISA、不同编译器或不同算法时，每条指令 / 每次操作代表的有效工作可能不同。评估程序快慢，优先比较同一任务正确完成的实际时间。

## Amdahl 定律：为什么局部加速有限

设旧总时间中可加速部分比例为 $p$，这部分被加速 $s$ 倍，其余不变：

$$S=\frac{1}{(1-p)+p/s}$$

推导可以直接画时间账本：旧程序 10 s，其中 8 s 可加速、2 s 不变。把 8 s 的部分加速 4 倍后，它变成 2 s；新总时间 $2+2=4$ s，整体加速 $10/4=2.5$ 倍。代公式时 $p=0.8$、$s=4$，结果相同。

即使可加速部分无限快，剩下的 20% 仍要执行，所以上限为 $1/(1-0.8)=5$。**p 是原运行时间所占比例，不是代码行数比例，也不是 CPU 核数。**

## 常见题的解题顺序

1. 先问要求的是 CPU 时间、总响应时间、吞吐量还是加速比。
2. 时钟题统一 Hz 与 s，先由频率取倒数得到周期；不能把频率直接当时间。
3. CPI 题先按指令比例算总周期或平均 CPI，再计算时间。
4. 局部优化题以旧总时间为 1 分账，减少被优化部分，再求整体比值。
