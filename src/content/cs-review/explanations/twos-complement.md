## 位串本身没有正负

计算机保存的是 0 和 1。`11111110` 如果按 8 位无符号整数解释，是 254；按 8 位补码整数解释，是 −2。**先看位宽和解释规则，再算数值**，不能只看最高位为 1 就永远判负。

1 bit 是一位；1 byte 通常是 8 bit。字长描述机器处理某类数据的自然宽度，不能据此认定所有指令、地址和浮点格式都恰好等于字长。

## 进制怎样转换

二进制从右往左的权值是 $1,2,4,8,16,\ldots$，所以 `10110₂` = $16+4+2=22$。十六进制使用 0–9、A–F，一位十六进制恰好对应四位二进制：`A6H` = `1010 0110₂` = 166。八进制一位对应三位二进制。

十进制整数转二进制，可反复除 2，余数从后向前读。例如 13 除 2 的余数依次为 1、0、1、1，反读得 `1101`。小数部分可连续乘 2 取整数位：0.625 → 1.25 取 1，0.25 → 0.5 取 0，0.5 → 1.0 取 1，因此 $0.625=0.101_2$。

十进制有限小数不一定能写成有限二进制小数，例如 0.1 会出现无限循环。机器只留有限位，因而需要舍入，后面的浮点精度问题就由此产生。

## 原码、反码、补码为什么出现

原码把最高位当符号，剩下表示大小：8 位 +5 为 `00000101`，−5 为 `10000101`。这容易看懂，却让正负零和加减法处理变复杂。

反码对正数不变，负数由对应正数逐位取反。补码对正数也不变；负数由相同位宽的正数**逐位取反再加 1**。8 位 −5：

```text
  +5   00000101
  取反 11111010
  加一 11111011   ← -5 的8位补码
```

补码可以让加减都利用模 $2^n$ 的二进制加法。例如 `5 + (-5)` 的低 8 位恰好为 0，最高的额外进位舍弃。它还有唯一的零。

| n 位解释 | 表示范围 | 8 位例子 |
| --- | --- | --- |
| 无符号 | $0$ 到 $2^n-1$ | 0 到 255 |
| 补码有符号 | $-2^{n-1}$ 到 $2^{n-1}-1$ | −128 到 127 |
| 原码 / 反码有符号 | $-(2^{n-1}-1)$ 到 $2^{n-1}-1$，有正负零 | −127 到 127 |

补码负数比正数多一个。8 位 `10000000` 是 −128，不是负零；在 8 位补码范围内无法得到其正相反数 +128。

## 补码转真值：两种方法任选

最高位是 0，按普通二进制求值。最高位是 1，可用“无符号值减 $2^n$”：`F2H` = 242，8 位补码真值 $242-256=-14$。也可以把位串取反加一，得到绝对值 14，再加负号。

**自编推演**：8 位 `90H` = 144 → $144-256=-112$；16 位 `0090H` 最高位为 0 → +144。同样出现 `90`，完整位宽不同，结果就不同。

把补码扩成更宽位数时要**符号扩展**：8 位 −5 为 `11111011`，扩成 16 位在高位补 1，变成 `11111111 11111011`。无符号扩展则高位补 0。只在数后面加 0 会改变数值，不是扩展。

## 溢出：先算真值，再检查范围

补码运算保留固定位数，但真实结果可能超出能表示的范围。8 位算 $100+60=160$，160 不在 −128 到 127 内，所以有符号溢出；低 8 位 `10100000` 若再按补码读是 −96，不能当成正确的数学和。

**加法规则**：两个同号数相加、结果变异号，发生有符号溢出；异号相加不会有符号溢出。硬件还可用最高位的进位入与进位出异或判断。减法 $A-B$ 的规则不同：A、B 异号而结果与 A 异号时溢出。

**CF 与 OF 不同**：CF 关注无符号进位 / 借位，OF 关注有符号范围。例如 8 位 `FFH+01H=00H` 有向外进位；解释成 −1+1=0 时却没有有符号溢出。$7FH+01H=80H$ 没有最高位外进位，却由 127+1 产生有符号溢出。具体减法 CF 的置位约定要看指令集，不能把某款 CPU 的标志照搬给所有 ISA。

乘法题先按真值计算精确积，再检查题目要求的结果宽度。两个 8 位数相乘可以用更宽结果保存；只有题目规定仅保留 8 位时，才按 8 位范围判断。例如 $(-14)\times(-112)=1568$ 无法保存为 8 位补码，但并非也无法保存到 16 位补码。

## 位运算、移位与 ALU

AND 逐位都为 1 才得 1，OR 有 1 就得 1，XOR 两位不同得 1，NOT 逐位翻转。用掩码 `x & 0x0F` 可取低四位；用 `x | 0x80` 可把第 7 位设为 1。位运算与逻辑真假运算不同。

逻辑右移在左端补 0；算术右移复制符号位。8 位 −8 `11111000` 算术右移一位为 `11111100`，即 −4；逻辑右移为 `01111100`，即 124。对负奇数，算术右移与程序语言的整数除法取整规则可能不同，不能无条件当同一操作。

左移丢弃高位、低位补 0。在没有溢出且按合适整数语义解释时可对应乘 $2^k$，但不能先忽略截断再声称所有左移都等于精确乘法。

ALU 即算术逻辑单元，完成加减、与或非、移位等运算，并按体系结构定义更新标志。补码把减法转成加负数，能让加减共享部分硬件。

## 浮点数：像二进制科学计数法

浮点格式用符号、指数和有效数表示数值，在有限位数里兼顾较大范围和一定精度。IEEE 754 binary32（通常称单精度）有 1 位符号 s、8 位阶码 E、23 位小数字段 f。

正规数的值是：

$$(-1)^s\times(1.f)_2\times2^{E-127}$$

**例子**：$5.5=101.1_2=1.011_2\times2^2$。所以 s=0，阶码为 $2+127=129$ 即 `10000001`，小数字段从 `011` 开始，其余补 0。正规数前面的隐含 1 不存进这 23 位，所以有效精度与字段长度不是一回事。

| 阶码 E | 小数字段 f | 含义 |
| --- | --- | --- |
| 1–254 | 任意 | 正规数 |
| 0 | 全 0 | 带符号的零 |
| 0 | 非零 | 次正规数，有效数前导为 0，指数用 −126 |
| 255 | 全 0 | 正 / 负无穷 |
| 255 | 非零 | NaN，表示非数类结果 |

不能把 E=0 直接代入正规数公式，也不能把 NaN 当普通可比较的实数。binary64 通常是 1/11/52 位、偏置 1023；它提高精度和范围，仍不能让所有十进制小数都精确表示。

浮点加减通常经历对阶、有效数运算、规格化、舍入、异常检查。对阶要把较小指数的数右移，可能丢失低位。保留位数有限，所以“大数加很小数”结果可能与大数相同；交换结合次序还可能改变舍入结果。

## 数值编码与字符编码别混用

BCD 用四位编码一个十进制数字，例如十进制 25 的 8421 BCD 是 `0010 0101`，而其普通二进制是 `00011001`。一个四位 BCD 数字只能用 `0000` 到 `1001`。

ASCII 定义基本字符的数字编码；Unicode 给字符统一分配码点；UTF-8、UTF-16 等是把码点编码成字节 / 编码单元的方案。UTF-8 是变长编码，ASCII 范围保持单字节；因此“一个字符总占一个字节”“Unicode 就是 UTF-8”都不对。

## 做题时的检查顺序

先圈出位宽、有无符号、编码与结果保留位数；再把原位串转成真值；用真值确认运算；最后检查范围和对应标志。浮点题额外先判断 E 是否属于正规数范围。能把 `90H` 在 8 位与 16 位中的含义解释清楚，就抓住了本章最重要的起点。

## 资料补讲：定点小数、移码与双符号位

同一个位串除了位宽，还要约定**小数点的位置**。若总长8位，1位符号、7位小数，补码值可按“8位补码整数值÷128”求出，范围为 $[-1,1-2^{-7}]$。位串 `10000000` 在这种定点小数格式中为−1；若按8位补码整数则为−128。小数点常是格式约定，不占一个额外存储位。

用总长5位、1位符号和4位小数表示 $-0.1101_2=-13/16$：原码为 `1.1101`；反码为 `1.0010`；补码为 `1.0011`。补码也能由 $-13\bmod32=19$ 得到位串 `10011`，再按4位小数解释。不要把整数补码的范围直接拿来判断定点小数，也不要把取反误写成取反加一。

**移码**是在真值上加偏置后保存。题目若明确8位移码偏置128，`9BH`的无符号值155对应 $155-128=27$；它若按8位补码解释却是−101。偏置128下的整数移码与同宽补码可通过翻转最高位转换，但IEEE 754单精度阶码偏置是127，不能把所有“偏置编码”都机械套成128。

教学中的双符号位补码以`00`表示未溢出的非负结果、`11`表示未溢出的负结果；`01`、`10`分别提示正向、负向溢出。它让检测更方便，不会扩大约定结果格式的有效数值范围，更不能“避免溢出”。解题仍应先求真实结果并检查范围。

## 资料补讲：从浮点位串反解，以及乘法结果宽度

反解binary32时先按1/8/23拆字段，再判断阶码是否属于特殊编码。例如 `C6400000H`：符号1，阶码140，真实指数 $140-127=13$，有效数为 $1.1_2=1.5$，所以值为 $-1.5\times2^{13}=-12288$。这里的13是二进制指数，不能把阶码140直接作指数；十六进制整串也不能按补码整数直接读成浮点值。

浮点对阶会移动尾数并改变指数以保持数值；规格化时，有效数绝对值偏小可左移并减指数，偏大可右移并加指数。舍入造成的新进位也可能需要再次调整。浮点数同样可能上溢或下溢，不能把指数域想成无限宽。

乘法溢出必须看**结果保存宽度**。8位补码 `F2H=-14`、`90H=-112`，精确积1568。它能放入16位补码，但不能放入8位补码；若只保留低8位得到`20H=32`，32不是精确积。看原始操作数“都只有8位”不能推出积也只需8位，溢出由题目要求的目标格式决定。
